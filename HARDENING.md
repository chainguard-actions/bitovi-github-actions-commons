## Findings Fixed

### unpinned-uses (severity: high)

Two `uses:` references in action.yaml are pinned to mutable version tags rather than immutable 40-character SHA digests, making the action vulnerable to supply-chain attacks if the upstream tag is moved or compromised.

- `uses: actions/checkout@v4` (tag `v4`)
- `uses: actions/upload-artifact@v3` (tag `v3`)

Both should be replaced with their full commit SHA, e.g. `actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4`.

Locations:

- `action.yaml:47992`
- `action.yaml:74200`

### script-injection (severity: high)

Multiple shell scripts invoked from the action's `run:` blocks expand env vars that are sourced from `inputs.*` and `github.*` contexts without double-quoting, violating rule (b). An attacker-controlled input value containing shell metacharacters (`;`, `|`, `&`, `$(...)`, whitespace, glob chars) can break out of the intended command context.

Key violations:

**deploy.sh**:
- `GITHUB_REPO_NAME=$(echo $GITHUB_REPOSITORY | sed ...)` — `$GITHUB_REPOSITORY` is unquoted inside command substitution.
- `if [ "$(alpha_only $ANSIBLE_SKIP)" == "true" ]` — `$ANSIBLE_SKIP` (from `inputs.ansible_skip`) is unquoted.
- `if [ "$(alpha_only $TF_STACK_DESTROY)" == "true" ]` — `$TF_STACK_DESTROY` (from `inputs.tf_stack_destroy`) is unquoted.
- `/bin/bash ... check_bucket_name.sh $TF_STATE_BUCKET` — `$TF_STATE_BUCKET` is passed as an unquoted positional argument.

**generate_identifier.sh**:
- `echo $GITHUB_REPOSITORY | sed ...` — `$GITHUB_REPOSITORY` is unquoted.

**generate_vars_terraform.sh**:
- `echo $GITHUB_REPOSITORY | sed ...` — unquoted.
- Dozens of `generate_var <name> $INPUT_VAR` calls pass input-derived env vars as unquoted second arguments (e.g., `generate_var aws_ec2_ami_filter $AWS_EC2_AMI_FILTER`, `generate_var aws_additional_tags $AWS_ADDITIONAL_TAGS`, etc.).

All of these env vars are set from `inputs.*` in the action's `env:` block and must be double-quoted wherever they are expanded in shell.

### github-env-injection (severity: high)

In `export_vars.sh`, the contents of the BitOps output file (`bo-out.env`) are written directly to `$GITHUB_OUTPUT` using `cat $BO_OUT >> $GITHUB_OUTPUT` without any newline sanitization. The `bo-out.env` file is generated by Terraform/BitOps from resource outputs that are derived from attacker-controllable action inputs (e.g., resource names, tags, identifiers). A malicious value containing a newline followed by `KEY=VALUE` would inject arbitrary key-value pairs into `$GITHUB_OUTPUT`, potentially overwriting outputs consumed by downstream steps. The required sanitization (`printf '%s' "$value" | tr -d '\n\r'`) is absent.

Locations:

- `operations/_scripts/deploy/export_vars.sh:9`
